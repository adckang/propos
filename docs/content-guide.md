# PROPOS Content Guide

## Purpose

- 운영 화면의 텍스트를 짧고 빠르게 이해되게 유지한다.
- 명사 나열보다 "상황 + 의미 + 다음 행동"이 드러나는 문장을 우선한다.
- 1명이 100개 숙소를 관리하는 상황에서 스캔 속도와 판단 속도를 높인다.

## Tone

- 탐색 요소는 짧고 예측 가능하게 쓴다.
- 버튼은 동사형으로 쓴다.
- 알림과 빈 상태는 짧은 구어체 문장으로 쓴다.
- 오류 문구는 문제, 영향, 복구 순서로 쓴다.

## Writing Rules

- 메뉴와 탭: `홈`, `체크인`, `모니터링`, `퇴실·청소`, `정산`
- 시스템 페이지 타이틀: `전체 관제 센터`, `퇴실 후 정리 현황`, `이번 달 수익 정산`
- 우선순위 섹션: `지금 할 일`, `지금 확인할 것`, `지금 먼저 볼 것`, `지금 먼저 처리할 것`
- 버튼: `청소팀 배정`, `정산 실행`, `메시지 보내기`, `대표 숙소 보기`, `이 단계 상세 패널 열기`
- 상태 칩: `정상`, `확인 필요`, `지금 대응`, `완료`
- 알림: `퇴실이 확인됐어요. 청소 배정이 필요해요.`
- 빈 상태: `지금 바로 확인할 알림은 없어요.`
- 오류: `도어락 상태를 아직 가져오지 못했어요. 잠시 뒤 다시 시도해 주세요.`

## Avoid

- 내부 구현 용어를 메인 타이틀로 직접 노출하지 않는다.
- 한 문장에 숫자, 약어, 전문 용어를 여러 개 섞지 않는다.
- 같은 뜻의 버튼/상태 라벨을 화면마다 다르게 쓰지 않는다.
- 과장된 감탄문이나 불필요한 장문 설명을 넣지 않는다.

## Preferred Patterns

- 상태 요약: `체크인 준비가 거의 끝났어요`
- 긴급 경고: `지금 확인이 필요한 숙소가 3곳 있어요`
- 완료 확인: `정산이 끝났어요. 보고서를 확인해 주세요`
- 수동 개입: `자동 처리에서 멈췄어요. 이 숙소만 확인해 주세요`
- 다음 행동 유도: `지금은 이 숙소만 확인하면 됩니다`
- 운영자 시점 제목: `이번 달 정산에서 먼저 볼 것`
